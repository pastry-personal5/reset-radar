# P1-M16: Watch sequence

Status: Planned

Implementation order and acceptance evidence for the [M16 overview](milestone-16-watch-overview.md). The [Watch app](../architecture/watch-app.md), [WatchSync](../architecture/watch-sync.md), [Application](../architecture/application.md), and [Watch UX](../ux-gui.md#apple-watch-app) define behavior; this sequence identifies the code and device handoffs.

## 1. Establish the implementation baseline

Record the current worktree revision, concurrent edits, test destinations, and focused baseline results. Inspect the M14/M15 code already present rather than requiring either milestone to pass its exit gate. Verify the actual iPhone `ReaderStore` transaction, post-commit pipeline, widget-origin catch-up, Forget Mac pending-clear state, Watch-related UI fields, App Group entitlements, and Watch target embedding. Confirm that the implementation still follows the transactional `WatchCacheStore` contract. Resolve a missing Watch handoff as M16 implementation work; leave unrelated M14/M15 device evidence with its milestone owner.

M9, M14, and M15 exit gates are outside M16's entry and closure checks. Keep their outcomes separate; do not infer Watch delivery or signing behavior from a relay, reader, or scheduling smoke test.

## 2. Implement and test WatchSync

Define one bounded property-list codec for versioned `WatchPayload` and `WatchEraseReceipt`, with explicit message kinds and rejection of malformed, oversized, unexpected-key, or unknown-version inputs. Assert that the typed payload and receipt contain no relay or provider secret fields. Keep the codec's envelope limited to the approved typed value. Define a typed empty refresh reply for the case where the iPhone has no permitted committed payload; it carries neither a fabricated clear nor a delivery revision. Build an injected `WCSession` boundary so activation, paired/app-installed state, reachability, remaining complication transfers, delegate callbacks, queued receipt delivery, and message-reply completion can be tested without a paired device.

Implement the iPhone `WatchLink` and Watch `PhoneLink` ports, using application context for the latest committed payload, budgeted `transferCurrentComplicationUserInfo` for the same payload, `sendMessage` with reply for active Watch refresh, and queued `transferUserInfo` for a receipt. Extend the iPhone port to expose the activated, paired, installed, complication-enabled, and remaining-system-transfer state needed by the existing budget policy; do not let a complication budget failure suppress application context. Surface both inbound payload channels as one typed stream and receipts as a separate iPhone stream. Keep inactive-platform implementations inert. Test duplicate callbacks, cancellation, activation changes, unreachable fallback, malformed inbound traffic, stream termination, and exactly-once reply completion under failure and timeout. [Apple's session contract](https://developer.apple.com/documentation/watchconnectivity/wcsession) requires activation and distinguishes background transfers from reachable live messages.

## 3. Wire the iPhone delivery and erasure path

Construct the `WatchLink` once in the iPhone app environment and activate the session at launch. After an app commit or transport-status change, run `ForwardToWatch`; after any commit whose pipeline does not finish, use the durable `needsAppReconcile` catch-up on the next app execution. Build the Watch payload from the current locked reader bundle, not a stale event snapshot: a newer commit or Forget Mac may have happened between event creation and send. Preserve the existing payload filter that removes transient manual-result identifiers. Persist a revision before delivery, and surface a failed context send as retryable so a later activation or execution resends it. On launch and session activation, resend a saved pending clear before any newer usage. Route typed receipts to `ConfirmWatchErase`; report storage failure separately from an irrelevant receipt, then read and send the current permitted snapshot only after a matching receipt clears the marker.

For a Watch refresh request, hold a bounded iPhone background assertion, run `IngestRelaySnapshot(.watchRequest)` subject to `ReaderRefreshPolicy`, and complete the WatchConnectivity reply once with the latest permitted committed payload even if the fetch is skipped, offline, or fails; return the typed empty reply if no payload is permitted. While erasure is pending, every reply contains the saved clear. Never start a manual Mac-assisted Codex refresh from this path. Put the reply deadline ahead of WatchConnectivity's timeout, so a slow fetch can fall back to the latest committed state; a late ingest may update ordinary application context after the reply. Verify revision durability before any send, replay after relaunch, stale or foreign receipts, and a late old relay result after Forget Mac.

Apply the persisted rolling complication budget only after checking activation, pairing, installation, enabled status, system transfers remaining, and changed standard Home values. Reserve a counted attempt transactionally before a transfer, define how a failed attempt affects later eligible changes, and verify that an exhausted or disabled complication never prevents application-context delivery. Serialize outgoing usage and clear sends with the Forget Mac handoff, and recheck the current reader bundle at the send boundary. Test the interleaving where an older forwarding task resumes after the clear was committed, so it cannot replace the saved clear in application context or a reply.

## 4. Compose the Watch app and its local controls

Create one Watch environment with `FileWatchCacheStore`, a read facade, `PhoneLink`, `CommitWatchPayload`, `RequestPhoneRefresh`, `EraseWatchData`, and a complication reloader. Route both payload channels and a nonempty interactive reply through the same commit use case. Keep the WatchConnectivity background task alive until its delivered content has completed durable commit and reload-request work, then complete it exactly once. On activation show the local cache immediately and request iPhone refresh only when reachable.

Build owner-confirmed Erase Watch Data and Reset Watch Pairing flows. Persist an empty cache, tombstone, and erase hold before requesting a complication reload; accept a newer clear and queue its receipt while held, but reject usage until explicit owner reset. For a changed installation, show a preview tied to the exact held payload and require confirmation before replacing the cache. Make storage and receipt-queue failures visible for retry, including a relaunch after the cache committed but receipt queuing failed. A `SurfaceReloader` call only requests a reload; verify the rendered frame on device and never claim that call proves erasure. Test interrupted writes, equal-revision conflicts, reordered channels, duplicate clear receipt, exact-preview replacement, and relaunch with a hold.

## 5. Build Watch presentation and complication

Use the committed Watch cache with `LoadHome` and Account Details read models. Replace the scaffold with the N-by-two five-hour/weekly ring matrix in stable Account List order, compact details, alias in details and accessibility, and appearance-aware #1 lavender, #2 mint, #3 peach palettes tied to stable global account numbers. Render percentage used, source, reset, freshness, offline, unavailable, and reset-awaiting-refresh states without inventing a zero or relying on color alone. Keep notification and Live Activity controls absent.

Replace the placeholder Watch widget with an account-window configurable complication for standard Home windows. Resolve exact saved identity from the Watch cache; a removed account/window stays unavailable. Emit a current entry and the Domain-derived presentation change instants, and request the next reload at the earlier known change or fifteen minutes; treat actual execution as system controlled. Use dynamic dates where appropriate, test delayed reload and original `observedAt` ageing, and reload after a durable commit or local erase. Inspect compact and larger families for readable state and alias treatment.
